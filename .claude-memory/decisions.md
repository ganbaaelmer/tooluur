# Архитектурын шийдвэрүүд — tooluur

## 2026-07-26 · Төслийн зорилго
Бар/пабд авсан юмаа согтуу байхдаа ч бүртгэж, барын хуурамч тооцоог
цаг хугацаатай баримтаар барих апп. Домэйн: `tooluur.website`.

## D-001 · Hosting: GitHub Pages (статик)
**Шийдвэр:** GitHub Pages + custom domain + GitHub-ийн үнэгүй Let's Encrypt SSL.
**Шалтгаан:** Хэрэглэгчийн тодорхой шаардлага («GitHub Pages деерээс шууд ажилладаг»).
Зардал 0, сервер ажиллуулах шаардлагагүй.
**Дүгнэлт:** Pages бол зөвхөн статик файл serve хийдэг → FastAPI/Postgres/Redis/Docker
backend үүн дээр **техникийн хувьд боломжгүй**. `ARCHITECTURE 2.md`-ийн backend
хэсэг бүхэлдээ энэ hosting-д хамаарахгүй болж байна.

## D-002 · Auth байхгүй
**Шийдвэр:** Login, signup, session, token — юу ч байхгүй.
**Шалтгаан:** Хэрэглэгчийн тодорхой шаардлага. Согтуу хүн нэр/пароль оруулахгүй.
**Үр дагавар:** JWT/OAuth2/rate-limit/`Depends(get_current_user)` дүрмүүд хамаарахгүй.
`localStorage`-д **access token хадгалахгүй** гэсэн дүрэм зөрчигдөөгүй — token гэж юу ч байхгүй.

## D-003 · State: `localStorage` (⚠️ стандартаас зөрчсөн)
**Шийдвэр:** Бүх дата `localStorage['tooluur.v1']`-д. DB байхгүй.
**Стандарт:** `ARCHITECTURE 2.md:40` — «Database = single source of truth. JSON file
DB-г орлож болохгүй». Мөн `:268` — «DB-ийн оронд JSON ашиглах бол ЗААВАЛ асуу».
**Шалтгаан:** D-001 + D-002-ын шууд үр дагавар. Backend байхгүй, хэрэглэгч байхгүй бол
хадгалах өөр газар байхгүй.
**Үнэ:** (а) төхөөрөмж хооронд sync хийх боломжгүй — найзууд тус тусын утаснаасаа
нэг тооцоо руу зэрэг бүртгэж чадахгүй; (б) хөтчийн датаг цэвэрлэвэл алга болно
(JSON export/import тавьсан).
**Статус:** ✅ 2026-07-26-нд хэрэглэгч зөвшөөрсөн. Стандартын `:40`, `:268` дүрмээс
зөрөх нь мэдээжийн, ухамсартай шийдвэр.

## D-004 · Frontend: vanilla JS (⚠️ стандартаас зөрчсөн)
**Шийдвэр:** Dependency-гүй HTML+CSS+JS, build step байхгүй.
**Стандарт:** React 18 + TS strict + Vite + Tailwind + TanStack Query + Zustand + sonner.
**Шалтгаан:** Backend/API байхгүй тул TanStack Query (server state) хийх юу ч байхгүй.
Согтуу хэрэглэгчид зориулсан 4 табтай апп нь framework-гүй ~1,600 мөрөнд багтсан.
Build step байхгүй нь Pages deploy-г маш хялбар болгосон. **Мөн энэ машин дээр
node/npm суугаагүй.**
**Статус:** ✅ 2026-07-26-нд хэрэглэгч «vanilla-гаар үлдэнэ» гэж шийдсэн.
React+TS+Vite+Tailwind хувилбар (бэлэн байсан сонголт) хэрэглэгчид харагдах шинэ
функц нэмэхгүй, зөвхөн стандарт нийцүүлэхийн төлөө байсан тул татгалзсан.

**Дараа нь React руу шилжих шаардлага гарвал:** UI логик нь `app.js`-д
`render*()` функцүүдээр тусгаарлагдсан, state нь нэг `S` объект + `normalize()`
дээр цэгцлэгддэг тул feature-based React бүтэц руу порт хийхэд `splitData()`,
`groupItems()`, `summaryText()` зэрэг цэвэр функцүүд бүтнээрээ дамжина.

## D-005 · Бүртгэлийн үнийг өөрт хуулж хадгална
**Шийдвэр:** Бүртгэл (`item`) нь `name`, `emoji`, `price`-аа бүртгэгдэх үедээ
өөр дээрээ хуулж авна — цэсний объект руу зөвхөн `drinkId`-аар холбогдоно.
**Шалтгаан:** Дараа цэсний үнэ солиход өмнөх түүхийн дүн хөдлөхгүй. Аппын үнэ цэн
бол баримт учраас түүхийг эргүүлж бичих боломжгүй байх нь зарчмын хэрэг.
**Дүрэм:** `item.price`-ыг ХЭЗЭЭ Ч эргүүлж бичихгүй.

## D-006 · Согтуу-тэсвэртэй UX
Хавтан 175×118px; нэг товшилт = нэг бүртгэл (тоо оруулах talbar байхгүй);
«Буцаах» доор үргэлж; устгал бүрт undo toast; тэглэх/хаах нь удаан дарж
баталгаажуулна; swipe/gesture байхгүй; харанхуй default (бар харанхуй байдаг).

## D-007 · Deploy: GitHub Actions (branch deploy БИШ)
**Шийдвэр:** Pages source = `GitHub Actions`. Workflow нь сайтын файлыг **нэрээр нь**
`_site/` руу хуулна (allowlist), дараа нь `upload-pages-artifact`.
**Шалтгаан:** `path: .` эсвэл branch deploy хийвэл repo-гийн БҮХ файл web-д гардаг —
`ARCHITECTURE 2.md`, `.claude-memory/`, `.gitignore` бүгд `tooluur.website/…` дээр
уншигдана. Хамгийн гол нь: хэн нэгэн санамсаргүй secret commit хийвэл тэр даруй
web-д serve болно. Allowlist нь тэр эрсдэлийг бүтцийн хувьд хаана.
**Түүх:** Эхлээд token-д `workflow` scope байгаагүй тул GitHub нь
`.github/workflows/pages.yml` push хийхийг татгалзсан → түр branch deploy-аар
залгасан → шинэ token (`workflow` scope-той) гарсны дараа Actions руу шилжүүлсэн.
**Шалгасан:** `/.env`, `/ARCHITECTURE 2.md`, `/.claude-memory/decisions.md`,
`/README.md`, `/.env.example` бүгд **404**; сайтын 9 файл бүгд **200**.

## D-009 · Үнэ засах нь нуугдмал байж болохгүй (v1.1.0)
**Асуудал:** Хэрэглэгч: «үнийг нь амархан editelmeer baina, тэгэхгүй бол энэ тогтмол
үнийг шууд ашиглах худлаа шүү». v1.0-д үнэ засах 2 арга байсан — хавтан дээр удаан
дарах (хэн ч мэдэхгүй) ба Цэс таб (гүн нуугдсан). Default үнэ нь таамаг байсан тул
тооцоо нь өөрөө худал гарах эрсдэлтэй байсан.
**Шийдвэр:**
- Грид дээр **«✎ Үнэ засах» режим**. Асаахад хавтан дарвал тоолохгүй, үнэ засах
  sheet онгойно. Ингэснээр хэвийн режимд хавтангийн 100% нь «+1» хэвээр —
  согтуу хүн санамсаргүй үнэ засахгүй (үнийг хавтангийн хэсэг болгож
  тапладаг хувилбарыг үүний ТӨЛӨӨ л татгалзсан).
- **Том keypad** (утасны гар биш): 58px товч, эхний цифр хуучин үнийг дардаг
  (калькулятор шиг) тул «цэвэрлэх» товч шаардахгүй. Компьютер дээр ч ижил.
- **«Дараах →»** товчоор бүх цэсийг дараалуулж тохируулна — 9 үнэ ~30 секунд.
- **⚠️ анхааруулга** нь `settings.pricesSet` false байх хугацаанд харагдана
  (хоосон үед бүтэн карт, тоолж байхад слим зурвас) → хэрэглэгч үнээ
  тааруулаагүйгээ мартах боломжгүй.
- Үнэ **0** бол «—» гэж харуулна — үнэ мэдэхгүй, зөвхөн тоолъё гэвэл болно.
**Режим таб солиход өөрөө унтарна**, гэхдээ нэг үнэ хадгалсны дараа унтардаггүй
(хэд хэдэн үнэ засахад дахин дахин асаах шаардлагагүй байхын тулд).

## D-010 · «Шинэ төрөл» ＋ хавтан гридэн дээр
**Шалтгаан:** Хэрэглэгч: «хүмүүс ганц төрлийн пиво захиалдгүй, өөр өөр төрлийг
захиалдаг». Цэс таб дотор нуугдсан «нэмэх» нь барандаа хэрэггүй — тоолж байгаа
дэлгэцэн дээрээ байх ёстой.
**Шийдвэр:** Гридийн төгсгөлд тасархай хүрээтэй `＋ Шинэ төрөл` хавтан.
Sheet дотор **хурдан нэрс** (Сэнгүр, Боргио, Tiger, Heineken…) — дарахад нэр +
emoji хоёулаа тавигдана → шинэ пиво нэмэхэд 3 товшилт.

## D-011 · Hero + footer
Hero нь **тооцоо хоосон байх үед л** харагдана (юм нэмэнгүүт хиймэл байдлаар
хаагдана) — онбординг нь хоосон дэлгэцийн үүрэг дүүргэх нь орон зай бас
хэрэглэгчийн анхаарлыг хэмнэнэ. Текст нь албархуу биш ярианы хэллэгтэй.
Footer: `Developed with ♥ by Ganbaa` — Тоолох ба Цэс таб дээр.

## D-008 · Service worker стратеги
HTML → network-first (шинэ deploy шууд хүрнэ), asset → stale-while-revalidate.
Дата localStorage-д тул cache цэвэрлэгдэхэд тооцоо алдагдахгүй.
