# Архитектурын шийдвэрүүд — tooluur

## 2026-07-26 · Төслийн зорилго
Бар/пабд авсан юмаа согтуу байхдаа ч бүртгэж, барын хуурамч тооцоог
цаг хугацаатай баримтаар барих апп. Домэйн: `tooluur.website`.

## D-001 · Hosting: GitHub Pages (статик)
**Шийдвэр:** GitHub Pages + custom domain + GitHub-ийн үнэгүй Let's Encrypt SSL.
**Шалтгаан:** Хэрэглэгчийн тодорхой шаардлага («GitHub Pages деерээс шууд ажилладаг»).
Зардал 0, сервер ажиллуулах шаардлагагүй.
**Дүгнэлт:** Pages бол зөвхөн статик файл serve хийдэг → FastAPI/Postgres/Redis/Docker
backend үүн дээр **техникийн хувьд боломжгүй**. `ARCHITECTURE 2.md`-ийн backend
хэсэг бүхэлдээ энэ hosting-д хамаарахгүй болж байна.

## D-002 · Auth байхгүй
**Шийдвэр:** Login, signup, session, token — юу ч байхгүй.
**Шалтгаан:** Хэрэглэгчийн тодорхой шаардлага. Согтуу хүн нэр/пароль оруулахгүй.
**Үр дагавар:** JWT/OAuth2/rate-limit/`Depends(get_current_user)` дүрмүүд хамаарахгүй.
`localStorage`-д **access token хадгалахгүй** гэсэн дүрэм зөрчигдөөгүй — token гэж юу ч байхгүй.

## D-003 · State: `localStorage` (⚠️ стандартаас зөрчсөн)
**Шийдвэр:** Бүх дата `localStorage['tooluur.v1']`-д. DB байхгүй.
**Стандарт:** `ARCHITECTURE 2.md:40` — «Database = single source of truth. JSON file
DB-г орлож болохгүй». Мөн `:268` — «DB-ийн оронд JSON ашиглах бол ЗААВАЛ асуу».
**Шалтгаан:** D-001 + D-002-ын шууд үр дагавар. Backend байхгүй, хэрэглэгч байхгүй бол
хадгалах өөр газар байхгүй.
**Үнэ:** (а) төхөөрөмж хооронд sync хийх боломжгүй — найзууд тус тусын утаснаасаа
нэг тооцоо руу зэрэг бүртгэж чадахгүй; (б) хөтчийн датаг цэвэрлэвэл алга болно
(JSON export/import тавьсан).
**Статус:** ✅ 2026-07-26-нд хэрэглэгч зөвшөөрсөн. Стандартын `:40`, `:268` дүрмээс
зөрөх нь мэдээжийн, ухамсартай шийдвэр.

## D-004 · Frontend: vanilla JS (⚠️ стандартаас зөрчсөн)
**Шийдвэр:** Dependency-гүй HTML+CSS+JS, build step байхгүй.
**Стандарт:** React 18 + TS strict + Vite + Tailwind + TanStack Query + Zustand + sonner.
**Шалтгаан:** Backend/API байхгүй тул TanStack Query (server state) хийх юу ч байхгүй.
Согтуу хэрэглэгчид зориулсан 4 табтай апп нь framework-гүй ~1,600 мөрөнд багтсан.
Build step байхгүй нь Pages deploy-г маш хялбар болгосон. **Мөн энэ машин дээр
node/npm суугаагүй.**
**Статус:** ✅ 2026-07-26-нд хэрэглэгч «vanilla-гаар үлдэнэ» гэж шийдсэн.
React+TS+Vite+Tailwind хувилбар (бэлэн байсан сонголт) хэрэглэгчид харагдах шинэ
функц нэмэхгүй, зөвхөн стандарт нийцүүлэхийн төлөө байсан тул татгалзсан.

**Дараа нь React руу шилжих шаардлага гарвал:** UI логик нь `app.js`-д
`render*()` функцүүдээр тусгаарлагдсан, state нь нэг `S` объект + `normalize()`
дээр цэгцлэгддэг тул feature-based React бүтэц руу порт хийхэд `splitData()`,
`groupItems()`, `summaryText()` зэрэг цэвэр функцүүд бүтнээрээ дамжина.

## D-005 · Бүртгэлийн үнийг өөрт хуулж хадгална
**Шийдвэр:** Бүртгэл (`item`) нь `name`, `emoji`, `price`-аа бүртгэгдэх үедээ
өөр дээрээ хуулж авна — цэсний объект руу зөвхөн `drinkId`-аар холбогдоно.
**Шалтгаан:** Дараа цэсний үнэ солиход өмнөх түүхийн дүн хөдлөхгүй. Аппын үнэ цэн
бол баримт учраас түүхийг эргүүлж бичих боломжгүй байх нь зарчмын хэрэг.
**Дүрэм:** `item.price`-ыг ХЭЗЭЭ Ч эргүүлж бичихгүй.

## D-006 · Согтуу-тэсвэртэй UX
Хавтан 175×118px; нэг товшилт = нэг бүртгэл (тоо оруулах talbar байхгүй);
«Буцаах» доор үргэлж; устгал бүрт undo toast; тэглэх/хаах нь удаан дарж
баталгаажуулна; swipe/gesture байхгүй; харанхуй default (бар харанхуй байдаг).

## D-007 · Deploy: GitHub Actions (branch deploy БИШ)
**Шийдвэр:** Pages source = `GitHub Actions`. Workflow нь сайтын файлыг **нэрээр нь**
`_site/` руу хуулна (allowlist), дараа нь `upload-pages-artifact`.
**Шалтгаан:** `path: .` эсвэл branch deploy хийвэл repo-гийн БҮХ файл web-д гардаг —
`ARCHITECTURE 2.md`, `.claude-memory/`, `.gitignore` бүгд `tooluur.website/…` дээр
уншигдана. Хамгийн гол нь: хэн нэгэн санамсаргүй secret commit хийвэл тэр даруй
web-д serve болно. Allowlist нь тэр эрсдэлийг бүтцийн хувьд хаана.
**Түүх:** Эхлээд token-д `workflow` scope байгаагүй тул GitHub нь
`.github/workflows/pages.yml` push хийхийг татгалзсан → түр branch deploy-аар
залгасан → шинэ token (`workflow` scope-той) гарсны дараа Actions руу шилжүүлсэн.
**Шалгасан:** `/.env`, `/ARCHITECTURE 2.md`, `/.claude-memory/decisions.md`,
`/README.md`, `/.env.example` бүгд **404**; сайтын 9 файл бүгд **200**.

## D-018 · Паб-хоппинг: «Шинэ газар эхлэх» (v3.1.0)
**Хэрэглэгч:** «shineer ehleh heseg ni oilgomjgui. hun neg gazar suuchaad
daraa ni uur gazar suuval yah we?»

**Асуудал:** Нэг шөнө хэд хэдэн газар суух нь энгийн хэрэглээ. Гэтэл шинээр
эхлэх цорын нэг зам нь хуудасны хамгийн доор нуугдсан hold товч байсан —
«газар нүүх»-тэй холбоотой гэж уншигдахгүй.

**Шийдвэр:** Урсгалыг **📍 газрын нэрэнд** амьдруулав (газар нүүхтэй
холбоотой ганц ойлгомжтой байрлал):
1. 📍 дарахад: нэр солих + (тооцоотой үед) «🏁 Өөр газар нүүсэн үү?» —
   «Энд N юм · X₮ тоологдсон. Дарвал түүхэнд хадгалагдаад шинэ газартаа
   0-ээс эхэлнэ. Юу ч устахгүй.»
2. «Шинэ газар эхлэх» нь **hold биш нэг товшилт** — устгадаггүй,
   архивладаг үйлдэлд hold шаардлагагүй (Material: confirm биш undo).
   Дараагийн sheet дээр «✅ ААА — 9 юм · 117,000₮ түүхэнд хадгалагдлаа
   [Буцаах]» + шинэ газрын нэр асууна.
3. **Буцаах** = архиваас бүрэн сэргээнэ (`unmove`): items, place, mode,
   heads, claimed бүгд буцна.

**Дагалдаж засагдсан:** архив өмнө нь `mode`/`heads`-ийг хадгалдаггүй байсан
тул (а) буцаахад алдагддаг, (б) архивласан шэрлэх-суултын хуваалцах текстэд
«N хүн шэрлэвэл» мөр гардаггүй байв — одоо хоёул хадгалагдана.

## D-017 · Нэг хуудас, 2 таб = 2 тооцооны хэлбэр (v3.0.0)
**Хэрэглэгч:** «eniig engej uur page deer bailgah ni zohimjgui bas sogtuu hun
oilgohod hetsuu baina. yur ni 1 pager bolgood 2 tabtai baimaar baina.»

**Асуудал:** 4 таб (Тоолох/Лог/Хуваах/Цэс) + «хэлбэр» гэсэн тусдаа ойлголт =
согтуу хүнд хоёр давхар навигаци. Тооцоог харахын тулд өөр хуудас руу очдог.

**Шийдвэр:** Навигаци бүхэлдээ **2 таб**, таб нь ӨӨРӨӨ тооцооны хэлбэр:
- Таб 1 «🤝 Шэрлэх», Таб 2 «🙋 Хүн тус бүрээр» (= `session.mode`)
- **Нэг хуудас**: hero → чипс(each) → грид → тооцоо → тулгалт → илгээх → хаах.
  Юм нэмэх болгонд доорх «Хүн тутамд»/хүн бүрийн дүн ШУУД өөрчлөгдөнө —
  тоолох болон үр дүн нэг дэлгэцэн дээр.
- **Лог** = totalbar-ын «N юм» товч дээрээс sheet-ээр. **Цэс** = баруун дээд ☰.
- `renderResult()` нь paint() бүрт дуудагдана — амьд тоолуур.
- Лог/Цэс sheet нээлттэй үед refresh() тэднийг ч шинэчилнэ (guard-тай).

Устгасан: setView/view, renderSplit, renderEditbar, modeCardsHtml, hero-ийн
setup хэсэг, modesw, goSplit/goCount — навигацийн ойлголт 1 давхарга боллоо.

## D-016 · «Хэн хэдийг төлөх» нь ГОЛ дэлгэц дээрээ байх (v2.3.0)
**Хэрэглэгч:** «hun tus bureer uyed daraa ni yaj hen hediig tulhuu yaj harhiin be?
salgaagui bugdiig ni niiluultsen yum shig baina.»

**Асуудал (шударгаар):** «хүн тус бүрээр» гэж сонгосон ч
- хавтангийн тоо нь **бүх хүнийг нийлүүлсэн** тоо байсан → «Би»-г сонгоод
  байхад «Шилэн пиво 2» гэж харагдах нь Би-гийн тоо биш, хэн ч уншиж чадахгүй;
- «−» нь хэн ч байсан сүүлчийнхийг хасдаг байсан;
- чип нь зөвхөн ТОО харуулдаг, дүн харуулдаггүй;
- хэн хэдийг төлөхийг харах цорын нэг арга нь өөр таб руу орох байсан.
Салгасны нь ямар ч ач холбогдол байгаагүй.

**Шийдвэр — 4 засал:**
1. **Чип дээр төлөх ДҮН гарна:** `Б Би 47,000₮`. `payFor(pid)` = өөрийн юмс +
   хамтынхаас эзлэх хувь. Асуултын хариу нь гол дэлгэц дээр, таб солихгүйгээр.
2. **Хавтангийн тоо = СОНГОСОН хүний тоо** (`tileCount`). Шэрлэх үед нийт.
3. **Тооны өнгө = сонгосон хүний өнгө** → «хэний тоо» гэдэг нь өнгөөр илэрхий.
4. **«−» нь сонгосон хүнийхээс хасна** — өөр хүний бүртгэлийг хөндөхгүй.

**«Хуваах» табын хүн тус бүр нь ТУСДАА баримт болов:** аватар, нэр (дарж
солино), **авсан юмс эмодзи × тоогоор** (`🍺2 🥃1 🍟1`), «өөрийн X + хамтын Y»
задаргаа, төлөх дүн Prata-гаар. Доор нь **нийлбэрийн тулгалт** —
«Нийлбэр 116,000₮ — нийт дүнтэй таарч байна ✓» (бөөрөнхийлөлтийн зөрүү
байвал шууд хэлнэ).

## D-015 · Үнэ засах = үнэ дээр дарах. Тусдаа режим АРИЛСАН (v2.2.0)
**Хэрэглэгч:** «unee tohiruulah geed tusdaa yum baih ni uneheer tuvugtei baina.
zugeer tuhain piwo etc deeree daraad shuud unee uurchildug baih ni amar shuudee.»

**Асуудал:** v1.1-д «✎ Үнэ засах» режим гаргасан. 1 үнэ засахад:
режим асаах → хавтан дарах → бичих → «✓ Дууслаа» = **4 товшилт + режимийн
ойлголт**. Согтуу хүнд «режим» гэдэг ойлголт өөрөө хэтэрхий хүнд.

**Шийдвэр:** хавтанг **3 тусдаа даралтын талбар** болгов:
| Талбар | Үйлдэл |
|---|---|
| том хэсэг (эмодзи + нэр) | +1 тоолох |
| **үнэ** (доод зүүн, хүрээтэй, ✎-тэй) | үнийг ШУУД засах |
| − (доод баруун, тоо байхад) | 1 хасах |

Одоо 1 үнэ засах = **1 товшилт + бичих**. Режим, товч, толгойд байлгах
төлөв юу ч байхгүй.

**Мис-тапын эрсдэлийг** ингэж барьсан: үнэ нь 34px өндөр жижиг таблет,
хавтангийн 134px-ийн доод зүүн буланд, хүрээтэй + харандаатай тул
«өөр товч» гэж уншигдана. Тоолохоор дарах том талбай нь 80% нь хэвээр.
Мис-тап болбол sheet онгойх — цуцлахад дата эвдрэхгүй тул эрсдэл хямд.

**Хажуугийн ашиг:** ямар ч үнэ дээр дарахад sheet-д «Дараах →» гарах тул
бүх үнийг дараалуулах flow нь тусдаа оролтгүйгээр өөрөө гарч ирдэг болов.

**Үнэ 0 бол «Үнэ?»** гэж гуулин хүрээтэй уриална. Мөн үнэ тохируулаагүй
байхад бүх үнийн таблет гуулин хүрээтэй болж, дарагддаг гэдгийг заана.

## D-014 · Хүний нэр — нэг удаа бич, дараа нь дар (v2.1.0)
**Хэрэглэгч:** «"Хүн 2" enter gelgui hunii ner tus buree oruuldag baimaar baih yum.»

**Хоёр эсрэг шаардлагыг би дараалан хэт даран шийдсэн:**
- v1.1: хүн нэмэхэд модал онгойж нэр бичих → «hun nemej hasah ni ih tuvegtei»
- v1.2: тэрийг даран автомат «Би / Хүн 2 / Хүн 3» болгов → нэр нь утгагүй,
  тооцоог найзууддаа илгээхэд хэн нь хэн болох нь мэдэгдэхгүй

**Зөв шийдэл — хоёуланг хангах:** нэр бичих ажлыг **нэг л удаа** болгох.
1. `＋` дарахад **нэг** sheet онгойж, нэр бичээд **Enter** дарахад шууд
   нэмэгдэж, **гар хаагдалгүй** оролт цэвэрлэгдэж дараагийнхыг бичихэд бэлэн.
   3 найз нэмэхэд 3 удаа модал онгойлгож хаах шаардлагагүй.
2. Бичсэн нэр бүр `S.recent`-д хадгалагдана (max 12). Дараагийн шөнө тэр
   sheet дээр «Хурдан нэмэх: ＋Батаа ＋Дорж ＋Сараа» гэж гарах тул
   **бичих шаардлагагүй, зөвхөн дарна**. Хассан нэр ч recent-д үлдэнэ.
3. `Enter` ажиллахгүй тохиолдолд оролтын хажууд `＋` товч бас байна.

**Цагийн хувьд зөв:** нэр бичих нь суулт эхлэхэд, харьцангуй эрүүл байхад
болдог. Согтуу үед зөвхөн чипс дарна. Тиймээс бичих нь «согтуу-тэсвэртэй»
зарчимтай зөрчилдөхгүй.

**Автомат нэр хаана ч байхгүй болов.** `each` руу сольход хүн байхгүй бол
автомат нэр үүсгэхийн оронд нэр оруулах sheet-ийг шууд онгойлгоно.

## D-013 · Дизайны систем: «даруухан гоё» (v2.0.0)
**Хэрэглэгч:** «orhoor goyo elegance designtai baih heregtei. odoo bol zugeer neg
startup-n trash haragdaj baina.»

**Асуудал:** v1.x нь системийн фонт + цэнхэр-хар + тод шар + бүх зүйл 2px хүрээтэй
хайрцаг байсан → ердийн dashboard харагдац.

**Шийдвэр — 4 зарчим:**
1. **Өнгө: цэнхэр-хар БИШ, бүлээн хар.** `#0B0A09` дэвсгэр, `#F3EEE7` (цаас шиг
   бүлээн цагаан, цэвэр `#fff` биш), акцент нь тод шар биш **гуулин алт `#D9A94E`**.
   Бар нь дэнлүүний бүлээн гэрэлтэй байдаг — тэр орчинд цэнхэр өнгө харь.
2. **Үсэг:** `Prata` (Didone сериф) зөвхөн ТОМ гарчиг, том дүн, sheet-ийн
   гарчигт. `Manrope` бүх UI-д. Жижиг шошгууд 11px, `.14em` зайтай, ТОМ үсгээр.
3. **Зураас:** 2px хүрээ → `rgba(...,.10)` үс зураас. Хайрцгийн тоог багасгаж
   зай + зураасаар зохион байгуулав (`.big--hero` нь хайрцаг биш зураас болов).
4. **Контраст:** гоё гэдэг нь ЖИЖИГ, БҮДЭГ гэсэн үг БИШ. Хавтан 126px, товч
   46-58px, тоо 28-52px хэвээр — согтуу хүн уншиж, оноход.

**Фонтыг өөртөө host хийсэн** (85 KB, 6 woff2, SW-д кэшлэгдэнэ) — гадаад сервер
дуудахгүй, офлайн ажиллана, CSP-д баригдахгүй.
⚠️ **Монгол Ө/Ү нь `cyrillic` subset-д БАЙХГҮЙ, `cyrillic-ext`-д байна**
(U+04AE, U+04E8). Тиймээс cyrillic-ext-ыг заавал татсан. Playfair Display-д
cyrillic-ext байхгүй тул татгалзаж Prata сонгосон.

**Хэлбэр + үнэ засах хоёрыг нэг зурваст нийлүүлэв** — тоолох дэлгэц дээрх
блокийн тоо 8 → 5 болов.

## D-012 · Хоёр төлбөрийн хэлбэр — энэ нь аппын ГОЛ зорилго (v1.2.0)
**Хэрэглэгчийн үг:** «Бар пабд сууж байхад юу захиалсанаа санахгүй үе их байдаг.
**Ихэнхдээ хүмүүс шэрлэж төлдөг.** Гэвч зарим тохиолдолд **хүн бүр тус тусдаа**
идэж уусан юмныхаа тооцоог хийх хүсэлтэй байдаг. Энэ хэдэн хэрэгцээг хангах
зорилгоор системийг хийж байгаа.»

**v1.1-ийн алдаа:** Систем зөвхөн 2-р хэрэгцээнд (хүнээр) зориулагдсан байсан.
Хамгийн түгээмэл хэрэгцээ — **шэрлэх** — нь тусдаа тооцоологддоггүй, хүн тутамд
хэдэн төгрөг болохыг гаргаж чадахгүй байсан. Мөн шэрлэхийн тулд ч хүн бүрийг
нэрээр нэмэх шаардлагатай байсан нь илүүц ажил (хэрэглэгч: «hun nemej hasah ni
ih tuvegtei baina»).

**Шийдвэр:** `session.mode` = `'even'` (default) | `'each'`.

| | 1. 🤝 Шэрлэх (default) | 2. 🙋 Хүн тус бүрээр |
|---|---|---|
| Хэрэгтэй мэдээлэл | зөвхөн **тоо** (хэдүүлээ) | хүний **нэр** + хэн юу авсан |
| Тохируулга | 2..9+ нэг товшилт | хүн нэмэх, юм хуваарилах |
| Тоолох дэлгэц | хүний зурвас **нуугдана** | хүний зурвас аватартай гарна |
| Гол хариулт | «Хүн тутамд 29,000₮» | хүн тус бүрийн дүн |

**Гол зарчим:** түгээмэл хэрэгцээнд (шэрлэх) **нэр хэрэггүй** — хүний тоо л хэрэгтэй.
Тиймээс шэрлэх үед хүнтэй холбоотой бүх UI нуугдаж, тоолох дэлгэц цэвэр байна.
`mode='even'` болоход `activePerson=null` болгоно — үзэгдэхгүй сонголт далд
хуваарилалт хийхээс сэргийлнэ.

**Хүн нэмэх нь юу ч бичихгүй:** ＋ дарахад «Би», «Хүн 2», «Хүн 3» гэж шууд
нэмэгдэнэ (модал байхгүй). Нэрийг дараа дарж сольж болно. `each` руу сольход
хоосон бол «Би» + «Хүн 2» автоматаар үүснэ — 0 товшилтоор ажиллаж эхэлнэ.

**Хуваарилалт хоёр замаар** (Plates by Splitwise-ийн зарчим):
- *Урьдчилан* — юм авахын өмнө хүнийг дарах.
- *Дараа нь* — «Лог» таб дээр бүртгэлийн нэрэн дээр дарахад дараагийн хүн болно
  (Хамтын → Би → Хүн 2 → …). Модалгүй, нэг товшилт. Согтуу үед урьдчилан
  сонгохоо мартах нь илүү магадлалтай тул энэ хоёр дахь зам чухал.

**Нэг юмыг 2 хүнд хуваахыг** дэмжээгүй (жишээ: 4 хүнээс 2 нь хуваасан салат).
Оронд нь «Хамтын» + тэнцүү хуваалт. Шалтгаан: бутархай хувь нэмэх нь согтуу
хэрэглэгчийн UI-г эрс хүндрүүлнэ. Хэрэв хэрэгтэй бол дараа нэмнэ.

**Бөөрөнхийлөлт:** хүн тутамд төлөх дүнг 100₮ дээш бөөрөнхийлж, үлдэх дүнг
(«300₮ үлдэнэ») тодруулж харуулна — барандаа хуваахад бутархай төгрөг тоолохгүй.

## D-009 · Үнэ засах нь нуугдмал байж болохгүй (v1.1.0)
**Асуудал:** Хэрэглэгч: «үнийг нь амархан editelmeer baina, тэгэхгүй бол энэ тогтмол
үнийг шууд ашиглах худлаа шүү». v1.0-д үнэ засах 2 арга байсан — хавтан дээр удаан
дарах (хэн ч мэдэхгүй) ба Цэс таб (гүн нуугдсан). Default үнэ нь таамаг байсан тул
тооцоо нь өөрөө худал гарах эрсдэлтэй байсан.
**Шийдвэр:**
- Грид дээр **«✎ Үнэ засах» режим**. Асаахад хавтан дарвал тоолохгүй, үнэ засах
  sheet онгойно. Ингэснээр хэвийн режимд хавтангийн 100% нь «+1» хэвээр —
  согтуу хүн санамсаргүй үнэ засахгүй (үнийг хавтангийн хэсэг болгож
  тапладаг хувилбарыг үүний ТӨЛӨӨ л татгалзсан).
- **Том keypad** (утасны гар биш): 58px товч, эхний цифр хуучин үнийг дардаг
  (калькулятор шиг) тул «цэвэрлэх» товч шаардахгүй. Компьютер дээр ч ижил.
- **«Дараах →»** товчоор бүх цэсийг дараалуулж тохируулна — 9 үнэ ~30 секунд.
- **⚠️ анхааруулга** нь `settings.pricesSet` false байх хугацаанд харагдана
  (хоосон үед бүтэн карт, тоолж байхад слим зурвас) → хэрэглэгч үнээ
  тааруулаагүйгээ мартах боломжгүй.
- Үнэ **0** бол «—» гэж харуулна — үнэ мэдэхгүй, зөвхөн тоолъё гэвэл болно.
**Режим таб солиход өөрөө унтарна**, гэхдээ нэг үнэ хадгалсны дараа унтардаггүй
(хэд хэдэн үнэ засахад дахин дахин асаах шаардлагагүй байхын тулд).

## D-010 · «Шинэ төрөл» ＋ хавтан гридэн дээр
**Шалтгаан:** Хэрэглэгч: «хүмүүс ганц төрлийн пиво захиалдгүй, өөр өөр төрлийг
захиалдаг». Цэс таб дотор нуугдсан «нэмэх» нь барандаа хэрэггүй — тоолж байгаа
дэлгэцэн дээрээ байх ёстой.
**Шийдвэр:** Гридийн төгсгөлд тасархай хүрээтэй `＋ Шинэ төрөл` хавтан.
Sheet дотор **хурдан нэрс** (Сэнгүр, Боргио, Tiger, Heineken…) — дарахад нэр +
emoji хоёулаа тавигдана → шинэ пиво нэмэхэд 3 товшилт.

## D-011 · Hero + footer
Hero нь **тооцоо хоосон байх үед л** харагдана (юм нэмэнгүүт хиймэл байдлаар
хаагдана) — онбординг нь хоосон дэлгэцийн үүрэг дүүргэх нь орон зай бас
хэрэглэгчийн анхаарлыг хэмнэнэ. Текст нь албархуу биш ярианы хэллэгтэй.
Footer: `Developed with ♥ by Ganbaa` — Тоолох ба Цэс таб дээр.

## D-008 · Service worker стратеги
HTML → network-first (шинэ deploy шууд хүрнэ), asset → stale-while-revalidate.
